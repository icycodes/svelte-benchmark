# SvelteKit i18n Lang Switcher with `hooks.server.js` and `transformPageChunk` ## Background Build a small SvelteKit application that supports three UI locales (`en`, `de`, `fr`) and exposes a language switcher. The user's chosen locale must persist across page reloads via a cookie, and the server must rewrite the root `<html>` element so its `lang` attribute reflects the active locale — exactly the kind of `app.html` rewrite that is normally tricky to get right in SvelteKit. The rewrite must be performed inside `src/hooks.server.{js,ts}` using the `transformPageChunk` option of `resolve` (see https://svelte.dev/docs/kit/hooks#Server-hooks-handle), not inside the page component, so the correct `lang` attribute is already present on the initial server-rendered HTML. The page must use Svelte 5 runes (`$props`, `$state`, or `$derived`) and SvelteKit form actions (with progressive enhancement via `use:enhance`) for the locale switch — the app must work with JavaScript disabled too. Supported locales and greetings: * `en` → "Hello, world!" * `de` → "Hallo, Welt!" * `fr` → "Bonjour, le monde !" The default locale (when no cookie is set or the cookie value is invalid) is `en`. ## Requirements * A SvelteKit project that builds and runs with **`@sveltejs/adapter-node`**. * Routes: * `GET /` — renders a page showing: * The greeting for the current locale (the exact strings above). * The current locale code in an element with `data-testid="current-locale"` (text content is the locale code, e.g. `en`). * Three locale buttons inside an HTML `<form method="POST">` that switches to the selected locale. The buttons must be `<button type="submit" name="locale" value="en|de|fr">...</button>`, each with `data-testid="locale-btn-<code>"`. * The form on `/` must POST to a SvelteKit form action that sets the `locale` cookie to the submitted value and redirects (HTTP 303) back to `/`. * `hooks.server.{js,ts}` must: * Read the `locale` cookie from the incoming request, validate it against the allowed set (`en`, `de`, `fr`), and fall back to `en` if missing or invalid. * Populate `event.locals.locale` with the resolved locale so server `load` functions can read it. * Use `resolve(event, { transformPageChunk })` to rewrite the `lang` attribute of the `<html>` element so the server-rendered HTML contains `<html lang="">`. * The root `+layout.server.{js,ts}` (or equivalent server load) must expose the resolved locale (e.g. as `data.locale`) to the page component. * Svelte 5: the `/` page (`+page.svelte`) must use at least one Svelte 5 rune (`$props`, `$state`, or `$derived`). * Progressive enhancement: the locale switch form must use `use:enhance` from `$app/forms` **and** also work without JavaScript (i.e. plain `<form method="POST">` with a valid form action). * The application must listen on port 3000 when started with the production build. ## Implementation Hints * Scaffold with `npx sv create` and pick Svelte 5 + the Node adapter, or add `@sveltejs/adapter-node` manually and run `svelte-kit sync` so the build works. * In `src/app.html`, leave the default `<html lang="en">` opening tag and rewrite it inside `transformPageChunk` using a string replace;
