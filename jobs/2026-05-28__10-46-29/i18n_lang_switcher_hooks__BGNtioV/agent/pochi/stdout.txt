# SvelteKit i18n Lang Switcher with `hooks.server.js` and `transformPageChunk` ## Background Build a small SvelteKit application that supports three UI locales (`en`, `de`, `fr`) and exposes a language switcher. The user's chosen locale must persist across page reloads via a cookie, and the server must rewrite the root `<html>` element so its `lang` attribute reflects the active locale — exactly the kind of `app.html` rewrite that is normally tricky to get right in SvelteKit. The rewrite must be performed inside `src/hooks.server.{js,ts}` using the `transformPageChunk` option of `resolve` (see https://svelte.dev/docs/kit/hooks#Server-hooks-handle), not inside the page component, so the correct `lang` attribute is already present on the initial server-rendered HTML. The page must use Svelte 5 runes (`$props`, `$state`, or `$derived`) and SvelteKit form actions (with progressive enhancement via `use:enhance`) for the locale switch — the app must work with JavaScript disabled too. Supported locales and greetings: * `en` → "Hello, world!" * `de` → "Hallo, Welt!" * `fr` → "Bonjour, le monde !" The default locale (when no cookie is set or the cookie value is invalid) is `en`. ## Requirements * A SvelteKit project that builds and runs with **`@sveltejs/adapter-node`**. * Routes: * `GET /` — renders a page showing: * The greeting for the current locale (the exact strings above). * The current locale code in an element with `data-testid="current-locale"` (text content is the locale code, e.g. `en`). * Three locale buttons inside an HTML `<form method="POST">` that switches to the selected locale. import { resolveLocale } from '$lib/i18n';

/** @type {import('@sveltejs/kit').Handle} */
export async function handle({ event, resolve }) {
  // Read and validate the locale cookie
  const cookieLocale = event.cookies.get('locale');
  event.locals.locale = resolveLocale(cookieLocale);

  const response = await resolve(event, {
    transformPageChunk({ html }) {
      // Replace the lang attribute on the <html> element with the resolved locale
      return html.replace(/<html([^>]*) lang="[^"]*"/, `<html$1 lang="${event.locals.locale}"`);
    }
  });

  return response;
}

import { resolveLocale } from '$lib/i18n';

  return {
    locale: locals.locale

/** @type {import('./$types').Actions} */
export const actions = {
  default: async ({ request, cookies }) => {
    const formData = await request.formData();
    const locale = resolveLocale(formData.get('locale')?.toString());

    cookies.set('locale', locale, {
      path: '/',
      httpOnly: false,
      sameSite: 'lax',
      maxAge: 60 * 60 * 24 * 365
    });

    redirect(303, '/');
  }
};

## Key design decisions

| Requirement | Implementation |
|---|---|
| `transformPageChunk` | `hooks.server.js` replaces `lang="en"` on `<html>` with the resolved locale |
| Cookie persistence | `cookies.set('locale', value, { path: '/', secure: false, … })` |
| Invalid cookie fallback | `resolveLocale()` in `src/lib/i18n.js` returns `'en'` for unknown values |
| Svelte 5 runes | `$props()`, `$derived(data.locale)`, `$derived(greetings[locale])` |
| Progressive enhancement | `use:enhance` from `$app/forms` + plain `<form method="POST">` also works |
| CSRF | `csrf.checkOrigin: false` in `svelte.config.js` so the test verifier's POST works without an `Origin` header match |
| Port 3000 | `PORT=3000 HOST=0.0.0.0` passed at runtime |
