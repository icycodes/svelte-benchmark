# SvelteKit Multi-Step Signup Wizard ## Background Build a multi-step signup wizard using **SvelteKit** and **Svelte 5 runes**. The wizard is split across three pages (`/signup/step-1`, `/signup/step-2`, `/signup/step-3`) and a final review page (`/signup/review`). State must be persisted between steps using **server-side sessions backed by cookies** so that data survives page reloads and direct navigation. Each step uses a SvelteKit **Form Action** in a `+page.server.{js,ts}` file with `redirect(303, ...)` to move to the next step on success, and `fail(...)` to return validation errors back to the same step. The UI must use Svelte 5 runes (`$props`, `$state`, `$derived`) and progressive enhancement via `use:enhance` from `$app/forms`. The signup data eventually collected across steps is: * Step 1: `email` (required, valid email format) * Step 2: `password` (required, length >= 8) and `confirmPassword` (must match) * Step 3: `firstName` and `lastName` (both required, non-empty) When the user clicks "Submit" on the review page, a final form action validates that all data is present, writes a new user record to a JSON file on disk, clears the session, and redirects to `/signup/done?email=<email>`. ## Requirements * A SvelteKit project that builds and runs with **`@sveltejs/adapter-node`**. * Routes: * `GET /` — redirect to `/signup/step-1`. * `GET /signup/step-1` — renders a form to collect the email. * `GET /signup/step-2` — renders a form to collect password and password confirmation. If `email` is missing from the session, redirect back to `/signup/step-1`. * `GET /signup/step-3` — renders a form to collect first and last name. If any of `email`/`password` is missing from the session, redirect back to the appropriate earlier step. * `GET /signup/review` — displays all collected fields (except the raw password) and a submit button. If any required field is missing in the session, redirect back to the appropriate step. * `GET /signup/done` — shows a success message including the submitted email taken from a query string parameter `email`. * Each `/signup/step-N` page (and `/signup/review`) has a Form Action that validates the submitted fields and, on success, stores them in the session and `redirect(303, ...)` to the next step (or `/signup/done` for the review page). * Validation errors must be returned via `fail(400, { ... })` so that the same page re-renders with an error message and the previously submitted value preserved (the password field does not need to be preserved). * Session storage: * Use a server-only session store keyed by a session id stored in an **HTTP-only cookie** (any cookie name is fine). * Session data must persist across page reloads and direct URL navigation within the same browser session, but is allowed to be lost when the server restarts (in-memory storage is acceptable). * The session cookie should be set on first request that has no session. * Final submission: * On successful submission from `/signup/review`, append the user record `{ email, firstName, lastName, passwordLength }` to a JSON file on disk (an array of users). `passwordLength` is the integer length of the chosen password. Do **not** store the raw password. * Clear the wizard session data after a successful submission, then redirect to `/signup/done?email=<email>`. * Svelte 5: each page component (`+page.svelte`) must use Svelte 5 runes (at least one of `$props`, `$state`, or `$derived`). * Progressive enhancement: every form must use `use:enhance` from `$app/forms` and must also work without JavaScript (i.e. plain `<form method="POST">` with a valid `action`). ## Implementation Hints * Scaffold with the SvelteKit CLI (`npx sv create`) and pick Svelte 5 with the Node adapter, or add `@sveltejs/adapter-node` manually. * Implement a small server-only session module under `src/lib/server/` exporting helpers such as `getSession(cookies)` and `saveSession(cookies, data)`; back it with a `Map<string, SessionData>` keyed by a random session id. * Read/write the session id from `event.cookies` inside `+page.server.{js,ts}` files (both inside `load` and inside `actions`). * Use `redirect(303, ...)` (from `@sveltejs/kit`) inside actions for post-submit navigation, and `redirect(303, ...)` inside `load` to send the user back to an earlier step when prerequisite fields are missing. * Use `fail(400, { field, message, value })` for validation errors so the page can show error messages and repopulate inputs from the returned `form` prop. * Persist completed signups to a JSON file inside the project directory (for example `data/users.json`). Make sure the parent directory exists before writing. ## Acceptance Criteria * Project path: /home/user/sveltekit-wizard * Start command: `npm run build && node build` (the Node adapter must be configured and the build must succeed) * Port: 3000 (the server must listen on port 3000; the `PORT` environment variable is set in the environment) * Routes (all accessible in a browser at `http://localhost:3000`): * `GET /` — redirects (HTTP 3xx) to `/signup/step-1`. * `GET /signup/step-1` — renders a form containing an input element with `name="email"` and a submit control. * `GET /signup/step-2` — renders a form containing inputs with `name="password"` and `name="confirmPassword"`. Visiting this route directly without first completing step 1 must redirect back to `/signup/step-1`. * `GET /signup/step-3` — renders a form containing inputs with `name="firstName"` and `name="lastName"`. Visiting directly without completing steps 1 and 2 must redirect back to the first incomplete step. * `GET /signup/review` — renders a summary of the collected fields and a submit button.
