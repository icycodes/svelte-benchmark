## What was built

### `src/lib/tree.svelte.ts` — Reactive data model
- Defines `FileNode` / `FolderNode` / `TreeNodeData` types
- `folder()` factory creates nodes where `open` is backed by an **individual `$state`** variable (accessed via a getter/setter), so toggling one folder is truly fine-grained and never re-mounts sibling subtrees
- Hard-coded demo tree: `src/`, `static/`, `tests/` folder hierarchy + 4 top-level files
- `class TreeStats` holds `openFolderCount` and `visibleFileCount` as **`$derived`** fields — the correct Svelte 5 pattern for exportable reactive computations from a `.svelte.ts` module

### `src/lib/TreeNode.svelte` — Recursive component
- Props declared with `$props()`: `{ node: TreeNodeData; depth?: number }`
- Imports and renders **itself** as `<TreeNode />` to recurse into children
- Folder rows carry all required attributes: `data-testid="folder"`, `data-folder-name`, `data-open="true"|"false"`, `▼`/`▶` indicator
- Children are inside `{#if node.open}` so closed-folder files are **absent from the DOM**
- File rows carry `data-testid="file"` and `data-file-name`

### `src/routes/+page.svelte` — Page with status bar
- Sticky header with `data-testid="open-folder-count"` and `data-testid="visible-file-count"` whose text content updates reactively from `treeStats`
- Renders the top-level tree entries via `{#each tree as node}<TreeNode {node} />{/each}`

### `svelte.config.js`
- Uses `@sveltejs/adapter-node` — the built server honours `PORT` env var (default 3000)
